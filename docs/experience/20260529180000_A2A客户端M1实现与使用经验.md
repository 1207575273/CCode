# A2A 客户端（M1）实现与使用经验

> 完成时间：2026-05-29
> 对应方案：`docs/plans/20260514190913_A2A编排控制台与服务发现总体方案.md`（M1 阶段）
> 范围：CCode 作为 A2A 客户端，让本地 LLM 能调用远端 A2A Agent。

---

## 1. M1 做了什么

让 CCode 成为 A2A（Agent2Agent）协议的**客户端**：本地 LLM 通过 `dispatch_remote_agent` 工具调用任意「已信任」的远端 A2A Agent，结果以流式形式在 CLI 复用 SubAgent 卡片渲染。

不在 M1 范围（留 M2/M3）：Web 编排控制台、服务发现拉取-预览、本机多实例发现、CCode 作为 A2A Server 被调用。

## 2. 文件清单与职责

| 文件 | 职责 |
| --- | --- |
| `src/a2a/types.ts` | 类型隔离层：re-export `@a2a-js/sdk` 协议类型 + 独立 `A2AEvent` union + `TrustedAgent` / `A2ADispatchResult` 领域类型。**唯一接触 SDK 的边界**，升级 SDK 只改这里 |
| `src/a2a/event-mapper.ts` | `mapToA2AEvent`：SDK 流式事件（Message/Task/StatusUpdate/ArtifactUpdate）-> 规范化 `A2AEvent`；`a2aEventToSubagentEvent`：投影成 CLI 现有 `SubagentEvent` |
| `src/a2a/client.ts` | `A2AClientWrapper`：封装 `ClientFactory`（显式传 JsonRpc+Rest transport）+ bearer 鉴权注入 + AgentCard 拉取超时 + cancel 本地兜底 |
| `src/config/a2a-config.ts` | `A2ATrustStore`：受信任白名单的异步读写（JSON 文件，原子写）；`maskToken` 脱敏；导出 `DEFAULT_FILE_PATH` |
| `src/tools/agent/dispatch-remote-agent.ts` | `DispatchRemoteAgentTool`（StreamableTool）：白名单校验 -> 流式调用 -> 投影事件 yield -> 结构化结果。依赖注入设计便于测试 |
| `src/commands/a2a.ts` | `/a2a` 命令：list/add/remove 白名单（同步 fs，复用 show_help action） |

## 3. 数据流

```
LLM 调 dispatch_remote_agent(agent, message)
   -> 白名单校验 (A2ATrustStore.findByUrl / alias / id)  [不在白名单则拒绝]
   -> registerSubAgent + yield subagent_spawn  (CLI 挂载卡片)
   -> A2AClientWrapper.sendMessageStream(message)
        每个 SDK 事件 -> mapToA2AEvent -> A2AEvent
                     -> a2aEventToSubagentEvent -> yield subagent_progress
   -> 终态: markSubAgentDone + yield subagent_done
   -> return A2ADispatchResult (JSON: status/output/artifacts/reason)
```

## 4. 使用方法

### 4.1 信任一个远端 Agent

```
/a2a add https://remote-agent.example.com 销售助手
/a2a list
/a2a remove 销售助手        # 按 url / id / 别名 移除
```

白名单存于 `~/.ccode/a2a-trusted.json`。M1 的 add **不拉取 AgentCard 验证**（信任用户输入），正式的「拉取 + 信任两步」在 M2 Web 端做。

### 4.2 让 LLM 调用

信任后，正常对话即可。LLM 看到 `dispatch_remote_agent` 工具描述，会在合适时机自动调用：

```
你：让销售助手查一下上季度成交额
LLM：(调用 dispatch_remote_agent, agent="销售助手", message="查询上季度成交额...")
     -> CLI 显示 a2a-remote 子 Agent 卡片，流式展示远端进度
     -> 返回结果
```

## 5. 关键设计决策（落地时的取舍）

- **A2AEvent 独立于 SubagentEvent**（方案 D-4）：SDK 的 Task 有 9 态生命周期 + artifact 增量，CCode 的 SubagentEvent 只有 spawn/progress/done 三态，塞不进去。故定义独立 union，在工具边界做一次投影复用 CLI 渲染。
- **类型隔离层**：所有下游只从 `src/a2a/types.ts` 导入，不直接 import `@a2a-js/sdk`。SDK 是 v0.x，接口会变，隔离后升级只改一处。
- **白名单是安全底线**（方案 D-5）：LLM 不能对任意 URL 发起请求，必须用户先 `/a2a add` 显式信任。`dispatch_remote_agent` 找不到白名单条目直接拒绝。
- **加入 SubAgent 黑名单**：`dispatch_remote_agent` 进了 `ALWAYS_EXCLUDE`，子 Agent 不能自主联网调远端（防递归 + 防失控）。
- **依赖注入**：`DispatchRemoteAgentTool` 构造可注入 `trustStore` + `createClient`，测试用 fake 不碰真实网络/文件。

## 6. SDK 踩坑记录（@a2a-js/sdk@0.3.13）

- **ClientFactory 必须显式传 transports**：`new ClientFactory({ transports: [new JsonRpcTransportFactory(), new RestTransportFactory()] })`，默认不带 transport，不传会无法创建 client。
- **流式事件 union**：`sendMessageStream` yield 的是 `Message | Task | TaskStatusUpdateEvent | TaskArtifactUpdateEvent`，用 `kind` 字段判别（'message'/'task'/'status-update'/'artifact-update'）。
- **TaskState 是连字符命名**：`'input-required'` / `'auth-required'` / `'canceled'`（单 l），不是下划线或双 l。
- **moduleResolution: bundler** 才能 resolve `@a2a-js/sdk/client` 子路径导出。
- **无 DOM lib**：项目 `lib: ["ES2022"]` 没有 `RequestInfo` 类型，fetch wrapper 参数用 `string | URL | Request`。
- **exactOptionalPropertyTypes**：可选字段无值时用条件展开 `...(x ? {k:x} : {})`，不能赋 `undefined`。
