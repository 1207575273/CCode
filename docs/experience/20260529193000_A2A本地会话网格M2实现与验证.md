## 1. 核心理念

**每个 CCode 会话 = 一个可寻址的 A2A Agent 节点。** 本地多开的会话不再孤立，能互相发现、互相委托。本地和远程统一走 A2A over HTTP，区别只在发现方式（本地 lockfile 自动 / 远程手动 add）。

## 2. 架构（方案 Y：每进程独立 A2A server）

```
会话A 进程                         会话B 进程
 ├─ 独立 A2A server :动态端口        ├─ 独立 A2A server :动态端口
 ├─ 写 ~/.ccode/instances/<sid>.json ├─ 写 lockfile 名片
 └─ dispatch_remote_agent ──HTTP──> └─ /a2a/rpc -> 本进程 sidechain AgentLoop 干活 -> 流式回
```

**端口动态、不靠猜**：每个会话把真实端口写进 lockfile 名片，其他会话扫 `~/.ccode/instances/` 目录发现彼此。

## 3. 文件清单

| 文件 | 职责 |
| --- | --- |
| `src/a2a/instance-registry.ts` | lockfile 发现：按 sessionId 写名片 + 10s 心跳 + 心跳过期AND进程死双判清理 + hostname/osUser 隔离 |
| `src/a2a/agent-card-builder.ts` | 动态 AgentCard：name/url/skills 从工具+cwd+git 派生 |
| `src/a2a/server-executor.ts` | AgentLoop -> A2A Task 流事件翻译 + 同步收集 |
| `src/server/a2a-routes.ts` | Hono 路由：GET /.well-known/agent-card.json + POST /a2a/rpc(send/stream) |
| `src/a2a/node-server.ts` | 节点启动门面：整合上述 + 起 HTTP server + lockfile 生命周期 |
| `src/tools/agent/dispatch-remote-agent.ts` | 客户端：解析优先级 本地会话(lockfile) -> 远程白名单 |
| `src/commands/a2a.ts` | /a2a list 展示本机活跃会话 + 远程白名单 |
| `bin/ccli.ts` | --web 启动时拉起本地 A2A 节点 + 退出清理 |

测试：92 个 a2a 单元/集成测试全绿（含 node-server 用真实 HTTP fetch 验证 well-known + rpc）。

## 4. 真机验证步骤（双终端）

> 单元层已验证（含真实 localhost HTTP）。带 LLM 的完整端到端需在真实双终端跑。

```bash
# 终端 1：项目 A
cd /path/to/projectA
ccode --web                 # 启动会话A,自动起 A2A 节点 + 写 lockfile

# 终端 2：项目 B
cd /path/to/projectB
ccode --web                 # 启动会话B,自动起 A2A 节点 + 写 lockfile
```

在会话 B 里：
```
/a2a list                   # 应看到"本机活跃会话 Agent"列出 projectA(及其端口)
```
然后对 B 的 LLM 说：
```
让 projectA 那个会话帮我读一下它的 README 并总结
```
预期：B 的 LLM 调用 `dispatch_remote_agent(agent='projectA', message=...)` -> 通过 A2A HTTP 调 A 的节点 -> A 本进程起 sidechain AgentLoop 执行 -> 结果流式回 B。

**手动验证节点可达**（不依赖 LLM）：
```bash
# 看 lockfile
cat ~/.ccode/instances/*.json
# 直接 curl 某会话的 AgentCard
curl http://127.0.0.1:<名片里的port>/.well-known/agent-card.json
```

## 5. 已知限制（MVP 范围）

- 本机 localhost 受信，**未做鉴权**（D-15 的 HMAC machine-id 留后续）
- contextId 不跨会话复用（每次调用新上下文）
- 被调用会话起的是 sidechain AgentLoop（独立于该会话的主对话，不污染主历史）
- 远程 Agent（外部 URL）能力同 M1：`/a2a add <url>` 手动信任
- Web 控制台拓扑可视化（M2a 完整版）未做，当前靠 `/a2a list` 文本
