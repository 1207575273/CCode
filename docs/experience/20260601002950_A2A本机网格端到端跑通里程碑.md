## 1. 里程碑

A2A 本机会话网格**端到端真机跑通**：一个 CCode 会话通过 `dispatch_remote_agent` 成功委托另一个本机会话执行任务并拿回结果。

## 2. 验证证据（真机）

环境：同目录启动两个会话
- 会话 A：sessionId `019e7ed8-e769-...`，端口 54751（发起方）
- 会话 B：sessionId `019e7ed8-56cf-...`，端口 54509（被调方）

在会话 A 执行：
```
dispatch_remote_agent(agent='54509', message='报告 cwd / PID / package.json version')
```
返回（10.8s，status=completed）：
| 项 | 结果 |
|---|---|
| cwd | `/d/a_dev_work/claude_cli_z01/cCli` |
| PID | `18115`（被调方进程，证明真由 B 执行）|
| version | `0.13.0` |

完整链路验证 OK：
```
会话A(54751) → dispatch_remote_agent → A2A HTTP(127.0.0.1) → 会话B(54509)节点
            → B 起 sidechain AgentLoop 执行 → 流式结果回传 A
```

## 4. 调试历程（踩坑记录）

1. **UUIDv7 前缀同源**：sessionId=uuidv7()，前缀是毫秒时间戳，同期会话前 6 位相同 → 显示截取无区分度。修复：展示完整 sessionId + 端口。
2. **198.18.x 代理虚拟网卡导致 dispatch 404**：getLanHost() 探到 Clash/v2ray 的 TUN 网卡地址（198.18.0.0/15），card.url 指向它被代理拦截 404。修复：本机统一用 127.0.0.1。（真机 curl + scripts/a2a-probe.mjs 诊断定位）

## 5. 已知设计点（正常，非 bug）

**被调方会话的主界面看不到 inbound 任务执行**：被调方收到 A2A 任务后起 sidechain AgentLoop（后台子 Agent），独立于其主对话，不注入历史、不显示在界面。设计意图：不让外部委托打断被调会话正在做的事。PID 证明任务确实在被调方进程执行。

## 6. 待办（后续推进）

### 待办 A：被调方可见反馈（产品体验）
当前被调方完全静默，用户不知道自己被调用了。可加（不打断主对话）：
- 被调方角落轻量通知 `[A2A] 收到来自 <端口> 的任务，已执行`
- 或 Web Agent 页 / Task 列表记录每次 inbound 调用（谁调的 / 任务 / 结果）
- 或状态栏闪烁提示 inbound 活动

### 待办 B：跨机器支持
详见 `docs/plans/20260601002326_A2A跨机器支持待办.md`：虚拟网卡过滤 + 鉴权 + bind/公布地址分离。

### 待办 C：鉴权（安全底线）
本机 localhost 当前无鉴权（同机受信可接受），但跨机器前必须做（D-15/D-16）。
