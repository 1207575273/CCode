## 0. 一句话

把 A2A 从"能调通但看不见"做成了"**双向、对称、不打断**的可视化协作"——
发起方和被调方都能在自己的界面里看到这次跨 Agent 调用的全过程，而这套可视化**没有新增一个 UI 组件**，全靠复用既有的 SubAgent 卡片与事件总线达成。

---

## 1. 背景：A2A 的 UI 盲点

A2A（Agent2Agent）让本机多个 CCode 会话互相寻址、互相委托任务。协议层早就跑通了：会话 A 通过 `dispatch_remote_agent` 委托会话 B 干活，B 起 sidechain 执行并把结果流式回传 A。

但"跑通"不等于"可用"。早期 UI 存在三个盲点：

| 盲点 | 现象 | 后果 |
|---|---|---|
| 被调方完全静默 | B 被调用后起后台 sidechain，B 的界面**毫无反应** | 用户不知道自己的会话正在被远程占用、在跑什么 |
| 调用无来源 | inbound 任务只有一段文本，不带"谁调的" | 即便想提示也不知道显示谁 |
| 单向可观测 | 只有发起方 A 能看到一张子 Agent 卡片；B 这端是黑盒 | 协作是双向的，可观测却是单向的 |

根因：被调方的 sidechain `AgentEvent` 流**只被翻译成 A2A 协议流回传发起方**，从未进入被调方自己的 UI 事件系统。被调方对"自己正在被调用"这件事一无所知。

> 注：被调方静默最初是**有意的设计**（M2 里程碑 §5），意图是"不让外部委托打断被调会话正在做的事"。本次突破的核心命题是：**如何在不打断主对话的前提下，把这件事变可见。**

---

## 2. 设计目标与原则

1. **双向对称**：被调方看到的执行过程，应与发起方看到的"对称"——发起方有什么卡片，被调方就有什么卡片。
2. **不打断主对话**（守住旧底线）：可见 ≠ 侵入。inbound 展示必须独立于被调方主对话的历史与输入流，主对话该干嘛干嘛。
3. **零新组件优先**：能复用既有 SubAgent 卡片 / 事件总线 / 状态栏的，绝不新造 UI。
4. **分层可见**：从"轻量感知"（状态栏一行）到"完整过程"（消息+工具时间轴）分级，按终端能力落地（CLI 状态卡 / Web 时间轴）。
5. **跨进程全景**：本机网格是多进程的，要能在一个界面看到整张网格的被调情况。

---

## 3. 架构总览：两条可视化通道

```
                         会话 A（发起方）                       会话 B（被调方）
                              |                                     |
  dispatch_remote_agent ------+                                     |
   + metadata['ccode:caller']={port,projectName}                    |
                              |  A2A HTTP(127.0.0.1)                 |
                              +------------------------------------> | a2a-routes 提取 caller
                              |                                      |
   [通道一] 发起方视角         |                          runTask 两层包装：               [通道二] 被调方视角
   A2A 流 -> subagent 事件     |                            recordInbound  -> node-status   (状态栏/网格页)
   -> 发起方 SubAgent 卡片     |                            mirrorInboundToUI -> eventBus    -> 被调方 SubAgent 卡片
                              |                                      |   (CLI 状态卡 + Web 时间轴)
                              | <----------- 流式结果回传 -----------+
```

两条通道各自独立、互不依赖，却渲染成同一种卡片：

- **通道一（发起方，原有）**：`dispatch_remote_agent` 把远端 A2A Task 流（`A2AStreamEvent`）投影成 `subagent_*` 事件，发起方 UI 渲染成"我调出去的子 Agent"卡片。
- **通道二（被调方，本次突破）**：被调方 sidechain 的 `AgentEvent` 流被镜像成 `subagent_*` 事件，被调方 UI 渲染成"别人委托我的"卡片（agentType=`a2a-inbound`）。

## 4. 突破点（做了什么 / 突破了什么）

### 突破 1：被调方从"黑盒"到"完整过程可见"

把被调方 sidechain 的 `AgentEvent` 流"镜像"一份成 `subagent_*` 事件发到进程内事件总线（eventBus），让被调方复用既有 SubAgent 卡片渲染：

- CLI：状态卡片（名字 / 轮次 / 当前工具 / 完成态）
- Web：消息 + 工具调用完整时间轴（SubAgentDrawer）

实现载体 `src/a2a/inbound-ui-mirror.ts`：一个 generator，夹在 `runLoop` 与 `executeA2ATask` 之间，**旁路 emit、原样透传**——既喂给协议层回传发起方，又喂给被调方 UI。

```
deps.runLoop  ->  mirrorInboundToUI(旁路 emit subagent_*)  ->  executeA2ATask(翻译成 A2A 流)
                            |
                            v
                     被调方 eventBus -> 被调方 CLI / Web 卡片
```

### 突破 2：可见而不打断（破解旧设计两难）

旧设计为了"不打断"选择了"完全静默"，是个非此即彼的取舍。本次找到了第三条路：

- 卡片走**独立的 subAgents 状态**，不写入主对话 messages / 历史 / JSONL。
- 主对话的输入、滚动、上下文完全不受影响。

于是"可见"与"不打断"同时成立——这是设计上的关键突破，而非简单加个提示。

### 突破 3：零新 UI 组件实现跨角色对称

最关键的工程洞察：**被调方 inbound 本质上就是一个"后台子 Agent"**，与本地 `run_in_background` 子 Agent 同构。而 UI 早已能渲染后台子 Agent：

- CLI `useChat` 的 eventBus 订阅本就处理 `subagent_progress` / `subagent_done`（无条件建卡）。
- Web `ChatPage` 本就处理 `subagent_spawn/progress/event/done` 全套（含时间轴）。

所以只要把 inbound 翻译成标准 `subagent_*` 事件，**两端自动渲染，无需任何新组件、无需改 useChat、无需改 ChatPage**。实际新增代码仅：1 个 mirror 模块 + 1 处 node-server 接线。

### 突破 4：调用来源可见（身份透传）

本机网格里 HTTP remote addr 只是 `127.0.0.1:临时端口`，无意义。突破做法：发起方在 A2A `message.metadata['ccode:caller']` 里带上自己的 `{port, projectName}`，被调方提取后用于卡片命名（"来自 :54751 的委托"）与状态栏来源显示。

链路：`dispatch-remote-agent`（读 `getLocalA2ANode()`）-> `client.buildSendParams(metadata)` -> A2A 协议 -> `a2a-routes` 提取 -> `runTask({caller})` -> 卡片/状态栏。

### 突破 5：跨进程全景聚合

inbound 活动是**各会话进程内**的状态（node-status 单例），单个进程拿不到别人的。突破做法：每个 A2A 节点暴露 `GET /a2a/inbound-activity` 端点，Web 网格页的 dashboard **并行拉取**所有本机节点的该端点，拼出整张网格的被调全景（谁正在被谁调、最近被调记录）。localhost 调用 + 短超时 + 失败降级，开销极小。

### 突破 6：分层可见，按终端能力落地

同一份数据，三种粒度的展示，覆盖不同使用场景：

| 层级 | 载体 | 内容 | 受众场景 |
|---|---|---|---|
| 轻量感知 | CLI / Web 状态栏 | "被调 \<来源\> 执行中 / 完成"（60s 衰减） | 我只想知道"有没有被调、好了没" |
| 执行过程 | CLI SubAgent 状态卡 | 名字 / 轮次 / 当前工具 / 终态 | 我想看它跑到哪一步 |
| 完整明细 | Web SubAgentDrawer | 消息流 + 每次工具调用入参/结果时间轴 | 我想看它具体干了什么 |
| 网格全景 | Web Agent 网格页 | 所有会话的被调记录聚合 | 我想看整张网格的协作情况 |

## 5. 具体改了什么（模块清单）

### 状态与记录层
- `src/a2a/node-status.ts`：进程内 A2A 节点状态 + 有界（环形 20 条）inbound 活动日志（`recordInboundStart/End`、`getInboundActivity`）+ caller metadata key 常量。
- `src/a2a/inbound-recorder.ts`：包装 A2A 流记录被调开始/终态（喂状态栏 / 网格页）。
- `src/a2a/inbound-ui-mirror.ts`：镜像 sidechain AgentEvent 成 subagent 事件（喂 SubAgent 卡片）。

### 协议与身份透传
- `src/a2a/client.ts`：`buildSendParams/sendMessage/sendMessageStream` 支持 metadata 透传。
- `src/tools/agent/dispatch-remote-agent.ts`：发送时带上 caller 身份。
- `src/server/a2a-routes.ts`：提取 caller、新增 `/a2a/inbound-activity` 端点。
- `src/a2a/node-server.ts`：`runTask` 两层包装（record + mirror）；接出 inbound 端点。

### 展示层（复用为主）
- `src/ui/StatusBar.tsx` + `useStatusBar.ts`：CLI 状态栏"被调"段。
- `src/core/event-bus.ts`：`status_bar` 载荷的 a2a 字段挂 inbound。
- `web/src/components/StatusBar.tsx`：Web 状态栏"被调"段（与 CLI 对齐）。
- `web/src/pages/AgentsPage.tsx`：Agent 网格页每会话卡片的"被调用"活动区。
- `src/server/dashboard/a2a-dashboard-api.ts`：跨进程聚合各节点 inbound。
- CLI `useChat` / Web `ChatPage`：**未改动**——SubAgent 卡片渲染直接复用。

## 6. 关键技术决策与权衡

| 决策 | 选择 | 理由 |
|---|---|---|
| inbound 展示形态 | 复用 SubAgent 卡片（agentType=`a2a-inbound`） | 与发起方对称、零新组件；而非新造独立面板或注入主对话 |
| 是否进主对话 | 否，走独立 subAgents 状态 | 守住"不打断主对话"底线 |
| 镜像注入点 | `runLoop` 与 `executeA2ATask` 之间的 generator | `executeA2ATask` 保持纯翻译不动，`recordInbound` 不动；旁路 emit + 透传 |
| 跨进程取数 | 节点 HTTP 端点 + dashboard 聚合 | inbound 是进程内态；不污染 lockfile、数据实时 |
| inbound 持久化 | 不持久化（仅进程内、环形 20 条） | 这是"活动感知"，非审计；进程退出自然消失，KISS |
| 来源标识载体 | A2A message.metadata（extension 约定） | 协议原生支持，不破坏 A2A 规范 |

---

## 7. 这套设计为什么"优雅"

- **同构复用**：认出"被调方 inbound == 后台子 Agent"，把一个看似新的需求映射到既有抽象上，新增代码极少。
- **关注点分离**：记录（status-bar）走 `recordInbound`，可视化（卡片）走 `mirrorInboundToUI`，协议翻译走 `executeA2ATask`，三者各司其职、互不耦合，都可独立测试。
- **对称性**："我调别人"和"别人调我"渲染成同一种卡片的两面，认知一致。
- **分层落地**：状态栏 / 状态卡 / 时间轴 / 网格全景，同一数据源喂四种粒度，按终端能力自然分流。

---

## 8. 边界与后续

当前不做（非 bug）：
- 跨物理机：未启用（需虚拟网卡过滤 + 鉴权，见跨机器待办）。
- inbound 不持久化、无完整 Task 回放（属 M3 `a2a_tasks` 持久化）。
- 本机 localhost 无鉴权（同机受信）。

后续可演进：
- 网格页从"被调记录列表"升级为"协作拓扑 + Task 时间轴"（M3）。
- 被调方对 inbound 任务的主动控制（暂停 / 拒绝 / 限流）。
- inbound 与发起方 Task 的端到端 trace 关联（call_chain 串联两端卡片）。

## 9. 一图回顾

```
跨 Agent 协作                      可观测性
─────────────                     ─────────
A 调 B          ──原有──>          A 看到"我调出去的"子 Agent 卡片
B 被 A 调       ──本次突破──>      B 看到"别人委托我的"卡片（CLI 状态卡 + Web 时间轴）
                                  + B 状态栏轻量提示"被调 <来源> 执行中/完成"
整张本机网格    ──本次突破──>      Web 网格页聚合所有会话的被调全景
                                  (全程不打断各自主对话)
```

突破的本质：把分布式 Agent 协作的**可观测性从单向补齐为双向、从黑盒补齐为全过程、从侵入式改造为旁路式**，且以最小代价（复用既有卡片与事件总线）达成。
